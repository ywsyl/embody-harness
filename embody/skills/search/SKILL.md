# 语义寻物（search）技能

## 1. 技能概述

本技能对接端侧**寻物算法服务**（云端视频流推理）。该服务**不是独立走完整段找物流程的执行体**，而是：

- 一个**视觉探测器**：机器狗在当前视野、原地旋转、以及**导航移动途中**持续检测目标；
- 一个**发现目标后的接管体**：一旦视觉发现目标，机器人应**立即停止当前导航**，由寻物服务接管运动控制并执行**靠近流程**，直到抵达目标旁。

寻物服务**只负责"视觉找到之后"的运控部分**；发现目标之前如何移动（漫游 / 前往下一搜索点 / 沿路寻找）由**导航服务**承载，两者**同步并发**进行：

```
导航服务驱动移动（智能体探索运控）──►（漫游 / 前往下一搜索点 / 路径行进）
        │  并        │
        └────────────┴─► 寻物服务并发检测（当前视野 / 原地旋转 / 路径上）
                           │
                    导航途中发现目标（已找到目标）
                           ▼
              智能体结束探索运控：取消当前导航任务（导航停）
                           ▼
            下发 ctl status=03（已结束探索运控）→ 算法接管运控
                           ▼
             寻物服务执行靠近 → 到达目标旁(status=13/23) → 19
```

**交互一律通过端侧 ROS2 topic**（订阅 `/findobj/search_status`、`/findobj/search_poll`，发布 `/findobj_ctl`），为**常驻订阅式集成**（参照 `Communicator/receiver.py` 常驻节点订阅事件的做法），**不是由任务循环临时跑一段脚本来阻塞执行**。发现目标后由智能体先停掉自己的探索运控、再以 ctl `status=03` 把运动权移交给算法（新增信令，见 4.1 / 7.1）。

### 能力边界（什么不做）

- 只用于**找物品/找物体**；**找人**走 `goto_find_person`；纯原地 360° 环视找物（不需要移动）走 `vision`（`--mode surround`）。
- 目标输入为**英文简单描述 prompt**（`sofa`、`red cup`、`man in red clothes`），只描述目标外观/特征，不含地点、导航、移动指令。
- **不负责发现前的移动**：跨区域、多搜索点的移动由导航服务提供；本服务只在导航并发下探测，找到才接管。
- 过程性语音（"我正在仔细找呢！别急别急等我看看" 等）由算法端自行播报，**不要重复 TTS**；Agent 只负责面向用户的**结果汇报**。

## 2. 适用场景

适用：

- "帮我找一下我的水杯"
- "在屋里转着找找红色的杯子，找到就靠近它"
- "找到穿红衣服的人"（指外观目标，仍属本技能找物范畴）
- 找需要走一段路才能看到的目标（导航漫游 + 寻物并发探测）

不适用（改用其它技能）：

- 找具体某人并交互 → `goto_find_person`
- 站在原地环视即可、无需移动的找物 → `vision` 的 `surround` 模式
- 单纯从 A 到 B → `waypoint_nav` / 视觉导航

## 3. 输入处理

| 需提取 | 必填 | 说明 |
|---|---|---|
| `prompt`（目标描述） | 是 | 用户中文指令 → **英文简单名词短语**：只描述物体/外观。例：水杯→`cup`、红色水杯→`red cup`、红衣的人→`man in red clothes`。禁含地点/动作/导航词 |
| `sn`（机器狗编号） | 多机时 | 指定由哪条机器狗执行寻物 |
| 搜索范围 / 是否需要移动 | 否 | 目标大概率不在当前视野时，需要与导航服务并发：漫游或前往下一搜索点，沿途让寻物持续检测 |

## 4. 运行与编排流程

> 编排侧以**订阅状态 + 下发控制**的方式推进（非阻塞脚本）。核心是**与导航同步、发现即停导航**。

### 4.1 控制信令（发布 `/findobj_ctl`）

- **开启探测**：`status=00`，携带 `prompt`。
- **主动结束**：`status=01`（端侧收到 `08` 表示已受理，随后到 `19`）。
- **查询**：`status=02`。
- **结束探索运控 / 移交运控**：`status=03` —— 目标**已找到**后，智能体先停止自己正在跑的探索运控（导航漫游 / 找点移动），下发 `03` 通知算法**接管运控**并执行靠近。

### 4.2 主循环

```
1. 解析出英文 prompt
2. 发布 status=00 开启寻物探测
3. 若当前视野无目标且需移动：启动/保持导航服务移动（漫游或前往下一搜索点），
   寻物探测与导航并发进行
4. 持续订阅 /findobj/search_status，按状态处理（见 4.3）
   核心规则：一旦导航途中回报"已找到目标"，智能体须先取消当前导航任务、
   结束自身探索运控，再下发 ctl status=03 把运控移交给算法执行靠近
5. 收到结束态(19)后按本轮结果向用户汇报；可下发下一轮开启
```

### 4.3 状态处理速查（扬帆总演示版为当前主用）

| 收到 | 含义 | 动作 |
|---|---|---|
| `07` | 初始化成功，云端开始推理 | 可告知用户"开始找了" |
| `10` | **发现目标，开始执行靠近流程** | 若仍在智能体探索运控下：**立即取消当前导航任务**（`POST /api/v1/navigation/cancel`，即 `nav_tools.cancel_navigation()`）结束探索运控，再下发 ctl `status=03`（已结束探索运控）**把运控移交给算法**执行靠近；向用户播报"找到目标了，正在靠近" |
| `13` | 成功到达目标旁边 | 告知用户已到达目标旁 |
| `23` | 找到目标 | "本轮找到"判定依据之一，向用户汇报找到 |
| `24` | 未找到目标 | "本轮未找到"判定依据，如实汇报 |
| `11` | 执行完搜索策略，始终没发现 | 未找到；可决定收尾或继续换点找 |
| `12` | 靠近过程中丢失目标 | 告知用户"又跟丢了，还在找"，回到导航/原地搜索 |
| `27`/`28` | 当前位置没有，将去/正在去下一处找 | 告知用户继续寻找中 |
| `25` | 下发 scene 与现有 scene 列表不匹配，**直接终止**本次寻物 | 说明原因并结束本轮 |
| `14` | 推理过程中拉流异常（>2s 无有效视频帧） | 异常，反馈后结束或重试 |
| `01`/`02` | 初始化异常：云端通信失败 / 接流失败 | 失败，反馈后结束 |
| `08` | 端侧收到结束信令（主动结束受理） | 等待 `19` 收尾 |
| `19` | 本轮任务结束，可下发下一次开启命令 | **收尾节点**：汇总结果汇报用户 |

### 4.4 常见状态流转

- 正常完成：`00 → 07 → 10 → 13 → 19`
- 目标丢失：`00 → 07 → 10 → 12 → 19`
- 视频流异常：`00 → 07 → 10 → 14 → 19`
- 初始化通信失败 / 接流失败：`00 → 01 → 19` / `00 → 02 → 19`
- 主动结束：`… → 08 → 19`

### 4.5 超时兜底

开启后长时间无新状态码时，用 ctl `status=02`（查询）核对 / 结合订阅的 `/findobj/search_poll` 判断当前阶段（**03 已用于"结束探索运控、移交运控"，勿再当轮询用**）；仍无进展可判定本轮异常，下发 `status=01` 结束并向用户反馈。探测期间若一直没有发现目标，需靠**导航持续换位置**（不能只停在原地等探测）。

## 5. 结果汇报（面向用户）

| 判定 | 依据 | 汇报示例 |
|---|---|---|
| 找到 | 本轮到过 `10 → 13` 或 `23` | "找到红色杯子了，我已经走到它旁边啦～" |
| 未找到 | 本轮到过 `11`/`24` 且最终 `19` | "没有找到红色杯子" |
| 中途失败/异常 | `01`/`02`/`14`/`25` | 说明原因，建议重试或换更具体的描述 |

## 6. 对接要求（集成侧）

> 端侧与编排侧的订阅/发布接入已按下方契约落地为**自包含阻塞脚本**（`scripts/`，见第 9 节）：一次 `search_and_approach` 工具调用内完成 开启→探测→移交→靠近→收尾。下方"常驻 ROS 节点 + 与导航并发"是**理想集成模型**（探测全程保持、导航移动不中断），需多进程/常驻改造时再按此升级；当前脚本一次调用内走完、探测期间不再驱动跨区移动。

- 在端侧常驻 ROS 节点（参照 `Communicator/receiver.py` 的 `AgentCloudBridge`）中：
  - 订阅 `/findobj/search_status` 与 `/findobj/search_poll`，把状态回传给任务编排逻辑；
  - 发布 `/findobj_ctl` 下发控制（`SN`/`prompt`/`status`）。
- 与导航服务**并发**编排：探测在导航进行中持续有效；
  - 导航途中确认目标已找到时，编排侧先**立即取消当前导航任务**结束自身探索运控（`cancel_navigation()` → `POST /api/v1/navigation/cancel`），**再下发 ctl `status=03`（已结束探索运控）** 由算法接管运控执行靠近；
  - 收到 `27`/`28`/`11`/`24` 等"此处没有"类状态、仍需继续时，由导航前往下一搜索点，探测保持开启。
- ROS 环境与仓库其它节点一致：`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`、`ROS_DOMAIN_ID=2`。

## 7. 信令接口附录

交互对象：端侧寻物算法节点。Topic 全部为端侧 topic。

### 7.1 控制信令（智能体 → 算法）`/findobj_ctl`

| 字段 | 含义 |
|---|---|
| `SN` | 哪条机器狗开启寻物功能 |
| `prompt` | 寻物目标，如找沙发即 `prompt: "sofa"` |
| `status` | 见下表 |

| ctl status | 含义 |
|---|---|
| `00` | 开始寻物 |
| `01` | 结束寻物 |
| `02` | 查询寻物 |
| `03` | **已结束探索运控**：此时已找到目标，智能体停止自身探索运控，**由算法接管运控**（执行靠近） |

注：

- 注1：原有 `scene` 表导航目标（如 `scene: "阳台"`）。**上层串接智能体后已剔除寻物自带的导航逻辑**，只保留视觉寻物 + 找到目标后的运控；移动由导航服务/上层集成并发承载。下发信令**不要携带 scene**。
- 注2：`status=03` 轮询时，任务中经 `/findobj/search_poll` 回报**最新状态码**；空闲待机回报 **`09`**。
- ⚠️ **文档自身冲突**：注2 仍将 `03` 描述为"轮询当前功能状态"，与上表新增语义（`03` = 结束探索运控、移交算法接管）冲突。SKILL.md 按**新增语义**落地（`03` = 移交运控）；触发 `/findobj/search_poll` 回报的轮询方式请以算法侧实际实现为准（`02` 查询可能即覆盖该需求）。

### 7.2 状态回报（算法 → 智能体）

| Topic | 说明 |
|---|---|
| `/findobj/search_status` | 寻物_状态：表示当前寻物处于哪个阶段 |
| `/findobj/search_poll` | 寻物_轮询：智能体定期轮询访问当前寻物阶段 |

`SN` 与 `prompt` 含义同 7.1，`status` 含义见 7.3 / 7.4。

## 8. 注意事项

- 一轮任务以收到 `19` 为结束标志；收到后可下发下一次开启命令。
- **探测阶段移动权在导航、发现目标后移动权在寻物**，两者不可同时驱动运动：确认找到目标后，先取消导航任务、下发 ctl `status=03`（已结束探索运控）完成移交，再由算法执行靠近，否则运动指令冲突。
- 只有当前真正"空闲待机"时轮询才回报 `09`；其余时刻回报当时最新状态码（轮询触发方式以算法实现为准，见 7.1 注2 冲突说明）。
- prompt 含地点/动作词时无法寻物，先交由导航处理移动、保持探测开启。
- 反复找不到时，提示用户换更具体的英文外观描述（如颜色 + 品类），不要无限重试。

## 9. 实现与运行（当前落地：自包含阻塞脚本）

当前任务循环以**阻塞工具**形态调用本技能（与 vision / waypoint_nav / move 一致），
不是常驻订阅式。一次 `search_and_approach` 工具调用在单次子进程内完成一轮寻物。

| 组件 | 位置 | 说明 |
|---|---|---|
| 端侧客户端脚本 | `scripts/findobj_search.py` | 独立 rclpy 节点：发布 `/findobj_ctl`（00 开启 / 03 移交 / 01 结束 / 02 查询），订阅 `/findobj/search_status`、`/findobj/search_poll`；按 4.3 状态推进，收到 `19` 或收尾窗口到期后输出 JSON 结果 |
| ROS 包装脚本 | `scripts/run_findobj_search.sh` | source foxy + cmcc_robot setup，设 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`、`ROS_DOMAIN_ID=2`，透传参数调用上者（仿 `run_asr.sh`） |
| 工具执行 | `plugin_tools/tool_executor.py` → `search_and_approach()` | `["bash", FIND_OBJ_SCRIPT, "--prompt", <英文目标>]` 子进程调用；脚本路径登记于 `configs/paths.py` 的 `FIND_OBJ_SCRIPT` |
| 工具清单 | `plugin_tools/available_tools.yaml` `search_and_approach` | 已补 `skill_path` 与 `output_format`（JSON） |

脚本行为要点：

- SN 缺省取环境变量 `FIND_OBJ_SN` → 设备配置 `factory/devSn`（可在 `--sn` 覆盖）。
- 发现目标（`10`/`23`）→ 尽力 `cancel_navigation()`（停探索运控）→ 发 ctl `status=03` 移交
  运控由算法执行靠近 → 等待 `13` / `19` 收尾。移交只在首次发现时发一次。
- 一轮以收到 `19` 为自然结束；若收尾窗口（`--settle`，默认 20s）内未等来 `19`、或总超时
  （`--timeout`，默认 180s），则发 ctl `status=01` 主动结束收口，避免占用会话。
- 长时间无新状态时发 ctl `status=02` 查询核对（`03` 已改语义、勿当轮询用）。
- stdout 仅输出一行结果 JSON：`{found, state, prompt, sn, message, last_status,
  round_ended, received_codes, elapsed_sec}`，供上层解析；诊断日志全部走 stderr。
- `--dry-run` 可自检参数解析与 SN 读取，不初始化 ROS、不发布话题。

自检：`bash scripts/run_findobj_search.sh --dry-run --prompt "red cup"`。
